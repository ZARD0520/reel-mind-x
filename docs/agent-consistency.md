# Agent 一致性与回归入口

2026-11-08。当前范围为画布编辑与异步图片生成的 Plan & Execute 闭环。

## 为什么此前逐轮发现问题

此前主要按具体操作验证闭环，但生成任务、后台回写、浏览器缓存和自动保存会同时改变同一节点。各路径分别处理状态、版本和保存基线，单条路径正确，并不能保证交错执行后仍正确。部分测试只覆盖一种返回顺序；因此“功能路径跑通”不足以作为稳定性结论。

本次将这些路径收敛到共享规则，并增加排列与调度测试。后续改动需从状态归属和整条链路判断影响，不能只增加某个入口的条件判断。

## 状态归属

| 状态 | 权威记录与写入方 | 观察方 |
| --- | --- | --- |
| 计划、执行步骤、租约、提交回执 | 持久化 Agent Run/Step；Planner 产出计划，Executor 经 MCP 执行 | 后台恢复、聊天查询 |
| 生成进度、版本、素材结果 | 生成任务及任务项；生成服务和 worker | MCP 查询、后台画布投影、浏览器 |
| 生成积分 | 既有 CreditHold/流水及事务结算 | Agent 不另设扣费通道 |
| 节点标题、提示词、位置、依赖 | 画布图；用户编辑和经过核验的 Executor | 生成提交校验当前输入 |
| 节点生成展示 | 任务结果的投影，受任务身份和版本约束 | 画布合并和客户端恢复共用规则 |
| 原助手回复 | 原 Run 的交付与媒体结果 | 后台更新原消息，客户端观察 |
| 客户端已确认图、待写意图、不确定写入 | 单个 `CanvasPersistence` 实例 | 自动保存、显式保存、同步、Agent 交接 |

## 必须维持的约束

1. **计划先持久化，再执行。** Planner 不直接修改画布；恢复使用已保存计划，缺少检查点时不能擅自重规划。
2. **提交可重放。** 生成步骤 UUID 用作请求幂等键；任务、积分预留、画布绑定和步骤凭证在同一事务提交。未知厂商结果不能自动重新发起生成。
3. **生成快照整体合并。** `generation-snapshot.ts` 将任务身份、状态版本、素材和展示结果作为一组处理，避免新任务绑定旧素材。版本只在同一任务内比较；不同已提交任务按服务端创建时间和任务 ID 排序。后台投影必须仍绑定原任务。
4. **只有一个客户端持久化协调器。** 自动保存、打开剪辑前保存、后台读取和 Agent 交接共用队列和确认基线。保存期间的后续用户操作必须保留，不能把旧响应当作最新意图。
5. **失败结果未知时先读后写。** 请求失败并不能证明事务未提交；保存重试前读取服务端，重放原意图及后续编辑。读取失败则不继续发送下一次不确定写入。请求有超时边界，旧页面生命周期的响应不能发布到当前视图。
6. **交付和完成分开。** `waiting_generation` 可以交付对话，但仍有后台工作；共享 `agent-lifecycle.ts` 决定活动、终态和可恢复中断。前置条件、核验等确定错误不能自动恢复执行。
7. **阶段核验尊重合法后续编辑。** 媒体提交前保存编辑阶段核验检查点；后续重命名不重复核验旧标题，实际生成参数和素材绑定仍受保护。

## 验证方式

| 约束 | 覆盖 |
| --- | --- |
| 结果乱序、重复投递、新旧任务竞争 | 共享快照测试遍历 6 次投递的全部 720 种排列，逐步核对身份、版本和素材一致性 |
| 保存、读取、撤销、网络失败和生命周期 | 纯协调器测试覆盖提交前/后失败、超时、交接、React 生命周期，以及 128 组各 24 步混合调度 |
| 持久化与付费边界 | 隔离 PostgreSQL 测试覆盖租约、并发、回执、恢复、事务回滚、积分和跨作用域拒绝 |
| 用户可见链路 | 8 个浏览器脚本覆盖 Agent、后台恢复、原任务恢复、保存竞争、撤销重做、提示词、引用和批量部分失败 |
| 模型与协议连接 | 单独运行真实 Planner，通过 MCP 和数据库执行；图片提供商使用模拟实现 |

## 统一入口

```bash
pnpm test:agent
pnpm test:agent --full
pnpm test:agent --full --live
```

默认运行共享包、前端单元测试及 Agent 离线/MCP 测试；`--full` 加入隔离数据库、生成可靠性、API/主站/后台构建及 8 个浏览器脚本，当前共 17 个检查组。首次失败即退出。数据库连接使用本地 `apps/api/.env`，数据库测试限制 localhost 且使用随机隔离 schema。浏览器要求主站已运行，默认 `http://127.0.0.1:5173`，可用 `E2E_BASE_URL` 指定。

`--live` 额外调用真实规划模型，会产生模型调用费用；图片仍为模拟提供商。默认及 `--full` 显式关闭真实模型调用。

本轮完整入口通过，真实规划测试另行通过。用例数量与具体记录见 [第二阶段自测](./canvas-agent-phase2-validation.md)。修改共享合并、生命周期或持久化协调器后，应重跑完整入口；新增时序问题先补共享规则或调度测试，再检查各消费者。

## 验证边界

覆盖单个活动画布视图与异步 Agent/生成回写，尚未提供完整多端协同编辑、离线持久化发件箱或任意自然语言语义证明。不带 `baseGraph` 的旧客户端仍使用整体图覆盖语义。没有访问生产 PM2 环境，也未调用真实图片生成提供商；本地通过不替代这两部分上线验收。发布需同步更新共享包、API 和主站，本次无需新增数据库迁移。
