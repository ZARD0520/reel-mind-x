# 生成任务可靠性 v1

## 运行与部署

先构建 contracts、ai-gen 并生成 Prisma Client，执行 `pnpm --filter @reel/db db:deploy`，再部署 API 和 Web。后台依赖 PostgreSQL 和 Redis；生产迁移必须在启动新 API 前完成。本地已应用迁移。

数据库是任务的事实来源，Redis 只负责调度。API 启动及每 3 秒扫描到期步骤、补发队列并修复任务汇总；多 API 实例通过唯一键、步骤 revision、数据库租约和写入令牌防止重复执行。队列全局并发 3，模型请求及下载的超时为 120 秒，租约 90 秒、每 15 秒续约；崩溃后的租约到期步骤会被重新调度。

## 请求与恢复

- `POST /generation-tasks`：必须传稳定 UUID `requestId`。相同用户、相同 requestId 和参数返回原任务；换参数返回 409。同一 canvas/node 同时只允许一个活动任务，批量 1/2/4 是同一个父任务下的独立子结果。
- `GET /generation-tasks?canvasId=...`：返回每个节点的最新任务，供刷新恢复。
- `GET /generation-tasks/:id`：查询原任务及每个子结果。
- `POST /generation-tasks/:id/resume`：只恢复已有 provider ID 的查询或已有结果的保存，绝不重新请求生成。
- 画布首次加载查询一次；仅存在排队、提交、生成或保存中的任务时每 3 秒轮询。全部完成、失败或进入待人工确认状态后停止轮询；新提交和手动恢复会主动刷新并重新启动需要的轮询。
- 失败反馈仅属于当前画布访问：进入前已失败的任务不重放 toast 或节点错误，刷新和重新进入也不恢复旧错误。当前访问内提交或实际观察到正在执行的任务，之后失败时才提示；离开画布会关闭该节点的提示。这个展示标记不写入画布，后台失败记录与保存检查点不删除。
- 旧的图片、视频及带项目/画布的文本接口兼容，但内部转为持久化任务。旧客户端若不传 requestId，仅能获得后台恢复，不能获得跨请求幂等保护。

后台状态为：`queued → submitting → generating（视频）→ saving → completed`，明确失败为 `failed`，无法确认为 `unknown`。画布进行中统一显示“生成中”，不展示排队、提交、保存等内部状态及重试过程中的临时错误，也不模拟百分比；最终失败通过 toast 提醒，并在节点内保留错误原因，不在提示词输入框下方展示。查询与保存的恢复按钮也放在节点内。批量结果终态一次性回填，重复轮询不重复创建节点。

## 重试边界

- 明确 429：等待约 15–18 秒后只自动重试一次（含首次共 2 次提交）。再次 429 就结束任务并释放节点锁，提示“模型繁忙，请更换模型或稍后再试”，方便用户切换模型。
- 明确参数/权限拒绝：失败并释放节点锁。
- 提交网络错误、超时、408/5xx 或提交中服务崩溃：结果待确认，保持节点锁，不自动重提。第三方不支持幂等或按客户端标识查单时，无法承诺跨网络的 exactly-once；需要人工核实第三方记录，不能直接解除锁重试。
- 视频拿到第三方 ID 立即落库；查询失败仅重查同一个 ID，连续 10 次失败后暂停，可“继续查询”；连续处理中超过 30 分钟也暂停。
- 已生成结果先落库，再下载/探测/写入素材。保存最多重试 5 次，之后可“重试保存”。本地文件使用稳定的子任务 ID，已保存文件复用，不重新生成素材记录。
- 网络不确定时，前端也不会将“暂时查不到任务”等同于“未提交”。

## 测试

`pnpm --filter @reel/api test:generation` 使用本机 PostgreSQL 的临时独立 schema，迁移后执行故障注入测试，结束删除该测试 schema。默认读取 packages/db/.env 的 DATABASE_URL，也可设置 TEST_DATABASE_URL。只允许本机数据库；第三方模型、查询、媒体下载均为模拟，不消耗生成额度。

覆盖并发幂等、节点锁、批量、越权、重启恢复、查询/保存失败、429、提交不确定、重复 worker、租约 fencing、Redis 不可用和前端批量回填。

## 当前边界

未接入积分冻结/结算、供应商账单对账、Webhook、多供应商切换、管理后台的人工核查工具。升级前已存在的旧队列任务没有持久化的第三方 ID，不能自动获得相同的防重复保证。文本/图片为同步生成接口，未拿到结果时无法像异步视频一样按第三方 ID 恢复。
